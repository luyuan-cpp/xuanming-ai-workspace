# 通用工程设计与编码原则（跨仓通用）

> 对应总仓入口 [AGENTS.md](../../AGENTS.md)。适用于全部挂载子仓的新增、修改、重构与评审；语言/引擎专属细则（如 C++ 裸指针与 muduo、Unity 小游戏 WebGL2/IL2CPP、Java Netty/Spring、Go Kratos ctx）以各子仓自身 `AGENTS.md` / `docs/rules/` 为准。

原则冲突时按以下顺序取舍：

`正确性 / 安全 / 数据强一致性 / 向后兼容 > 简单 / 可读 / 与仓库一致 > 可维护 / 可测试 > 有数据支撑的性能 > 假想扩展`

偏离本文件原则必须有当前需求或证据支撑，并在注释、设计文档或交付说明中记录原因与代价。

## 1. 模块职责、设计模式与 Actor 消息隔离

- **单一职责（SRP）与高内聚低耦合**：一个类 / 模块只对一种变化原因负责；协议适配、业务策略、持久化存储与 UI 表现严格分离，依赖单向不成环，拒绝无隔离价值的透传层与万能 `Manager`。
- **组合优于继承**：优先组合可替换组件构建能力，继承仅用于稳定的 is-a 契约。
- **23 种经典设计模式的使用原则**：严禁为了套模式而无故堆砌抽象层；但当某个结构确实适合用 GoF 23 种设计模式（策略、状态、工厂、适配器、责任链、观察者、模板方法、命令等）来解耦、消除巨型 `if/switch` 分支或隔离明确变化轴时，**主动采用或向程序建议采用，并明确告诉程序为什么用这个模式**（解决了什么具体痛点、替代了什么更糟的写法）。
- **系统 / 模块间消息通信（Actor 隔离，强制）**：
  - **状态私有**：每个业务系统 / 模块独占自身可变状态，禁止跨模块直接读写内部字段，禁止在消息中传递可变对象引用。
  - **不可变消息驱动**：跨系统、跨线程、跨进程交互一律通过显式定义的**不可变消息**（Mailbox / 事件 / RPC / Kafka）通信，禁止跨模块直接同步调内部实现或借全局单例/共享缓存绕过消息通道。
  - **串行消费与防错**：各 Actor / 所属线程串行消费消息队列，靠所有权与幂等键保证一致性；跨边界契约显式处理超时、乱序与重复投递。
  - **作用边界清晰（防过度设计）**：上述约束仅适用于**系统 / 模块之间与跨线程、跨进程边界**；单个模块内部保持正常直接方法调用，**严禁把模块内部普通函数无意义地拆成消息**。

## 2. 简单、标准与第三方开源库选型

- **KISS / YAGNI / DRY**：未上线阶段玩家数据可清空，按最标准方案直接落地与重构，不堆砌历史兼容包袱；一条业务真相只保留一个权威源。
- **命名第一原则**：详见 [naming-and-boundaries.md](naming-and-boundaries.md)——清晰易懂、语义准确、标明物理单位。
- **第三方开源库选型（强制三步法）**：
  1. **优先标准库与官方核心框架**：标准库或现有基础框架能简洁解决的不引入第三方库。
  2. **按当前开发语言去 GitHub 找同语言同类头部高 Star 项目**：Star 门槛随语言生态体量浮动（大生态通用库参考 ≥ 2 万 Star、同类取高 Star 且维护活跃；垂直/细分组件按对应生态综合评估）。
  3. **交由程序决定并说明原因**：不擅自默默引入新依赖，把候选库与“是否自研”交给程序决定，并写清引入理由、代价、依赖树与风险对比；**安全与平台兼容性永远优先于 Star 数**。

## 3. 正确性、并发与生命周期

- **Fail-closed 与提交点原子性**：不可信输入在入口严格校验；关键归属/资产写回必须带围栏（`owner_epoch` / CAS / 事务），禁止吞错或静默降级；排查出的问题当场闭环，不留“以后再修”的债务。
- **默认不私自新开独立线程 / 后台 goroutine**：除非压测数据证实瓶颈确需新增独立工作/消费线程，且**必须先与程序/负责人确认并说明原因与压测依据**。
- **连接与异步回调生命周期**：连接所有权唯一且清晰；异步回调回到逻辑/主线程时，第一步先校验目标对象、玩家、连接与会话代次是否仍存活且一致，失效则直接丢弃。

## 4. 实例与布局分层（强制）

一条记录只回答一个问题：**「它是什么」**，还是**「它摆在哪」**（适用于背包、装备、宠物、队伍站位、技能栏、时装坐骑、邮件附件等）：

- **实例层只描述实体**：身份（`guid`）、模板（`config_id`）、数量、状态、时间戳，不混入 `pos` / `slot` / `index` / 排序等摆放字段；
- **布局层只描述排列**：容量、槽位、占位与整理策略，不混入领域实体；
- **不混用字段**：不靠数组 / `repeated` 下标承载业务槽位语义；纯内存展示态不写入持久化结构。
